# Known quirks inherited from the original thesis pipeline

This refactor is a faithful port: the pipeline's numeric behavior was kept
identical to the original thesis code wherever changing it would alter the
regressor's inputs. This page documents the quirks that were **deliberately
preserved** (with a note on what a "corrected" version would look like), and
one artifact bug this refactor's validation surfaced and fixed.

## 1. `solidity` is not the standard solidity ratio

`features.extract_shape_features` computes:

```python
solidity = area / cv2.convexHull(largest, returnPoints=False).size
```

Standard solidity is `contour_area / convex_hull_area`. `cv2.convexHull(...,
returnPoints=False).size` returns the **number of vertices** in the convex
hull, not its area -- so this feature is really "contour area per hull
vertex", not a solidity ratio. This is a bug in the original thesis code
(`Test.extract_shape_features_edited`, `defect_analysis.py`).

It is reproduced exactly because the published regressor (R^2 ~= 0.97) was
trained on features computed this way. A corrected reference implementation:

```python
hull_area = cv2.contourArea(cv2.convexHull(largest))
true_solidity = area / hull_area if hull_area else 0.0
```

Retraining with `true_solidity` instead is a reasonable follow-up experiment,
but it changes the model and should be validated (and reported) separately,
not silently substituted.

## 2. The segmentation mask is not a clean binary image

`segmentation.crop_to_mask` draws contours in white onto a *copy of the
original color crop*, then thresholds that per BGR channel. The graphene
lattice bonds (rendered in red) survive as colored speckle around the
highlighted defect void rather than disappearing into flat black -- visible
in the thesis's own figures (Section 3.1, "Crop di YOLO dopo la
trasformazione"). `features.extract_shape_features` was tuned against masks
with exactly this look (it re-binarizes with Otsu's threshold before finding
contours, which happens to work despite the speckle). See the docstring of
`segmentation.py` for the exact sequence of operations preserved.

## 3. The original `energy_dataframe.csv` lost its sample identifier

While validating this refactor against the committed historical CSVs
(`data/tables/box_dataframe.csv`, `groupedDataframe.csv`, `energy_dataframe.csv`),
per-defect features were confirmed to match bit-for-bit
(e.g. `graphene_100134`'s two defect boxes reproduce every digit of
`box_dataframe.csv`'s `area_px`, `perimeter_px`, `circularity`, ... columns).

However, `energy_dataframe.csv` itself has **no sample-id column** -- its
first column is an unnamed `0..N` row index. The original notebook grouped by
`nome_imm`, merged on that index level with `total_energy_dataset_df`, then
saved the result with `to_csv()` (default `index=True`); the merge silently
dropped the index's name, so the saved file cannot be traced back to the
samples it describes.

`dataset.aggregate_by_sample` / `dataset.merge_energy_labels` in this
refactor always keep `sample_id` as an explicit column, so the corresponding
`data/tables/grouped_dataframe.csv` / `energy_dataframe.csv` regenerated by
`gdd build-dataset` remain traceable to their source `.xyz` files.

## Numeric parity check

Running the refactored pipeline (`dataset.build_modeling_dataset` +
`modeling.train_regressor`) over the committed `data/masks/` and
`data/xyz/` with `test_size=0.1, random_state=13` (the original notebook's
split) reproduces:

- **1985** rows in the per-sample modeling table -- matching the
  `X.shape == (1985, 7)` printed in the original `main_playground.ipynb`.
- **R^2 = 0.973** on the held-out test set -- matching the thesis's reported
  `0.9711437904543666` within the variance expected from a different
  scikit-learn version.

This is the strongest possible evidence the port preserves the original
pipeline's behavior end to end, not just module-by-module.
